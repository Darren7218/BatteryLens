# Architecture and complexity

`BatteryReadings` reads supported Android sensors and preserves unavailable values. `CalibrationStore` owns charging-session continuity, cold settings (`battery_lens`), hot runtime state (`battery_runtime`), and saved history; `CapacityEstimator` owns the pure robust capacity fit. `TrendSamplingPolicy` decides when a trend point is worth keeping. `AppWorker` serializes all storage, database, sensor-scan, and analysis work onto a single daemon thread, while `TrendRepository` owns WAL-mode SQLite persistence (`trends` and `sessions` tables, plus one-time preference migration). `BatteryMonitorService` adapts polling cadence to plug/screen state and debounces noisy broadcasts; `MonitorWatchdogJobService` provides persisted `JobScheduler` charging and periodic recovery. `InsightAnalysis` and `TrendAnalysis` consume immutable snapshots; `CsvExports` owns file formatting; `MainActivity` lazily builds tabs and releases chart/cache memory when backgrounded or trimmed.

| Operation | Work | Reason |
| --- | --- | --- |
| Decide whether to retain a point | O(1) | In-memory fast filter compares the new reading to the latest point before queuing work. |
| Append a reading | O(log N) indexed write; N ≤ 2,300 | WAL SQLite uses a time index and compiled `SQLiteStatement`s; pruning runs periodically (`PRUNE_INTERVAL = 24`). |
| Read/chart k points | O(k) | Drawing or exporting k readings visits them once; custom views pre-allocate all `Paint`, `RectF`, and `Path` objects. |
| Fit charging capacity | O(n + B²), B ≤ 26 | A linear pass selects SOC bins; at most 325 wide-separation comparisons remain. |
| Render unchanged session journal | O(1) | Cache the 60-session list from SQLite until its revision changes; cleared on UI stop/trim. |

Android compatibility: `minSdk 24` supports Android 7.0 through Android 17 (`compileSdk 37`, `targetSdk 37`). Feature-specific APIs are guarded cleanly by SDK version (`JobScheduler` 24+, notification channels 26+, `computeChargeTimeRemaining` and accessibility headings 28+, `WindowInsets` / `WindowInsetsController` / `ApplicationExitInfo` 30+, FGS exception checks 31+, `POST_NOTIFICATIONS` / receiver flags 33+, `EXTRA_CYCLE_COUNT` / `EXTRA_CHARGING_STATUS` / `specialUse` FGS 34+, edge-to-edge system bars 35+, `EXTRA_CAPACITY_LEVEL` 36+). `MainActivity` caps content width at `640dp` for large/foldable screens on Android 16–17. `PowerEventReceiver` resumes monitoring via `BatteryMonitorService.startFromBackground` (falling back to a tap-to-resume notification if background FGS launch is denied) and `MonitorWatchdogJobService.schedule` on `BOOT_COMPLETED`, `QUICKBOOT_POWERON`, and `MY_PACKAGE_REPLACED`. Release builds use R8 code shrinking (`minifyEnabled true`) and `shrinkResources true` with zero third-party runtime dependencies.

Migration: on first database access (`battery_trends.db` v2), `TrendRepository` and `CalibrationStore` import `live_trends_v1` trend points and `calibration_sessions_v2` / legacy `calibrations` sessions into SQLite inside transactions before removing the old preference keys, and `CalibrationStore` splits volatile runtime state out of `battery_lens` into `battery_runtime`. The database is capped at 2,300 trend points (7 days) and 60 calibration sessions.
